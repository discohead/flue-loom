# Authoring a Flue agent

Every agent is a single `.ts` (or `.mts`, `.js`, `.mjs`) file in `<workspace>/agents/`. The filename minus extension is the agent name (kebab-case recommended).

## Canonical shape

```typescript
import type { FlueContext } from '@flue/sdk/client';

export const triggers = { webhook: true };

export default async function ({ init }: FlueContext) {
  const agent = await init({ model: 'anthropic/claude-haiku-4-5' });
  const session = await agent.session();
  const result = await session.prompt('Your task here.');
  return { text: result.text };
}
```

Three required pieces: the import, the `triggers` export, the `default export async function`.

## Imports — which entry?

| Import path | When |
|---|---|
| `@flue/sdk/client` | **Default for handlers.** Platform-agnostic. Exports `Type`, `connectMcpServer`, all types. |
| `@flue/sdk/node` | Node-specific helpers (rare in handler code). |
| `@flue/sdk/cloudflare` | CF-specific helpers (rare in handler code). |
| `@flue/sdk` | Tooling/build only. Don't use in agent files. |
| `@flue/sdk/internal` | SDK-internal. Never use. |

`@flue/sdk/client` re-exports types: `FlueContext`, `FlueAgent`, `FlueSession`, `AgentInit`, `Command`, `SessionEnv`, `ToolDef`, `BashFactory`, `SandboxFactory`, plus `Type` (from pi-ai) and `connectMcpServer`.

The Flue examples sometimes use `import type { FlueContext } from '@flue/sdk'` — that re-exports work too, but `/client` is the documented entry. Prefer it.

## `FlueContext<TPayload, TEnv>`

Generic over your payload and env shapes (compile-time only, no runtime validation):

```typescript
interface MyPayload { question: string; }
interface MyEnv { ANTHROPIC_API_KEY: string; }

export default async function ({ init, payload, env, id }: FlueContext<MyPayload, MyEnv>) {
  // payload.question is typed as string
  // env.ANTHROPIC_API_KEY is typed as string
  // id is the request id (used as default agent id)
}
```

For Cloudflare, pass the `Env` interface generated by `wrangler types`.

## `init(options?)` options at a glance

```typescript
const agent = await init({
  id: 'custom-id',                          // defaults to request id
  cwd: '/workspace',                        // override session cwd
  sandbox: 'empty' | 'local' | factory,     // see flue-sandboxes
  persist: customStore,                     // defaults to platform store
  model: 'anthropic/claude-haiku-4-5',      // 'provider/modelId'
  role: 'friendly',                          // agent-wide role default
  tools: [myTool],                           // agent-wide tools
  commands: [myCmd],                         // agent-wide commands
});
```

## Return values

The return value of the handler is what the HTTP route returns to the caller. Whatever JSON-serializable value you return goes back as the `result` field of the `{ result }` envelope.

Use structured results for typed call sites:

```typescript
import * as v from 'valibot';

const out = await session.prompt('What is 2+2?', {
  result: v.object({ answer: v.number() }),
});
return out;  // { answer: number }
```

## Conventions

- Tabs for indentation (matches Flue's own style).
- ESM only. Use `import` not `require`.
- Use `.ts` extensions in relative imports (`allowImportingTsExtensions` is on by default).
- Prefer `import type` for types — `verbatimModuleSyntax` requires explicit type imports.
- Don't mutate the request `payload`. Treat it as readonly.
